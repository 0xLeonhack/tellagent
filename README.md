# tellagent

> **改口就是破绽。**

盯 SEC 文件的**变化**：公司每个季度交同样一批文件，但内容在悄悄改。tellagent 把这些改动挑出来、判断重不重要，重要就叫醒一个 agent 去查清楚。

---

## 1. 问题

上市公司按季度、按年度提交同一批文件。**内容是会变的**：

- 风险因素章节悄悄新增一段"供应链集中度"
- MD&A 的语气从乐观转为谨慎
- 会计政策在脚注里换了口径
- 竞争对手从"我们面临竞争"变成点名道姓

这些全部是公开信息，法律要求披露。**问题是没人读得起。**

逐字比较一家公司两期 10-K 是个研究项目；而一个投资者要盯的是一整个持仓。

现有工具都不解决这件事：

| 现状 | 为什么不行 |
|---|---|
| AI 财经新闻过滤 | 赛道拥挤，而且它盯的是「新消息」，不是「变化」 |
| 逐家公司文件对比工具 | 手工、按次、贵，覆盖不了持仓 |
| 人工读年报 | 只能抽样，漏掉的正是没被预期到的那部分 |
| **没人回答的问题** | 这个变化是**全行业都在说**，还是**只有这一家在说**？ |

---

## 2. 核心洞察

**洞察一：信号是「变化」，不是「消息」。**

一条新闻所有人都看到了。一家公司**偷偷改了自己的措辞**，只有读过两个版本的人知道。而"变化"比"消息"值钱——它是公司自己的行为，不是外界的噪音。

**洞察二：廉价的眼睛，昂贵的手。**

大模型可以判断，但贵，所以大家都在省着用、抽样看、事后看。

Jev 这类「判断模型」把判断的成本压到了不用省的程度。于是架构可以变成：

- **判断便宜到可以永远睁着眼** → 全量、持续地看着每一条文件
- **行动昂贵所以极其吝啬** → 只有真的值得时才叫醒 agent

这不是为了套 agent 的概念，**这是唯一能让「一直盯着」和「不乱花钱」同时成立的结构。**

**洞察三：检测只是线索，验证才是结论。**

"这家公司新增了一段供应链风险" —— 这**不是结论，是线索**。

真正的问题是：**同行也在说同一件事吗？**

- 全行业都在写 → 宏观噪音
- 只有这一家在写 → 真实的公司特有信号

回答这个问题意味着要读十家同行的同一章节。**没人有这个时间。** 而这是一个天然的多步、要用工具、要综合判断的任务——**这正是 agent 的位置。**

## 3. 它怎么工作

```
┌──────────────────────────────────────────────────────────────┐
│ perceive   发现变化                                            │
│            轮询 EDGAR · 抽章节 · 段落对齐 · 算精确 diff          │
│            （全由代码完成，见 ARCHITECTURE.md「设计决定一」）      │
└───────────────────────────┬──────────────────────────────────┘
                            │ 候选变化段落（几十条，大部分是噪音）
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ judge      Jev 判断                                            │
│            实质性？类别？方向？重要性？紧急度？                    │
│            便宜到可以全量跑 —— 永远睁着眼，几乎从不说话             │
└───────────────────────────┬──────────────────────────────────┘
                            │ 重要性 > 阈值？
                            ▼
┌──────────────────────────────────────────────────────────────┐
│ act        agent 醒来                                          │
│            同行也在说吗？→ 是噪音还是信号                         │
│            昂贵、稀有 —— 只在该发生的时候发生                     │
└───────────────────────────┬──────────────────────────────────┘
                            ▼
                     带引用的短备忘
```

**一句话**：这是一个 **99% 的时间在打盹的 agent**。它一直在看，但它几乎从不醒。醒的时候，说明真的有东西。

## 4. 终端里长这样

```console
$ tell watch portfolio.txt
  watching 40 filings · 4,128 paragraphs judged · $0.031 · 0 tells

$ tell watch portfolio.txt
  ⚑ AAPL · risk factors · supply-chain concentration · +1 new paragraph
     waking investigator...
     peers: MSFT — no change · GOOG — no change · DELL — no change
     → 这家公司特有的信号，不是行业性的
```

`0 tells` 那一行就是"在打盹"。它变成 `⚑` 的那一秒，就是这个项目存在的理由。

---

## 5. 它不做什么

这些边界是刻意的，破了项目就站不住：

- **不做投资建议。** 它回答的是"你该先读哪一份"，不是"你该不该买"。定位是**注意力分配**。
- **不声称预测能力。** 它指出"这个信号一直在公开文件里，只是没人读得起"，不说"这预示着股价会跌"。
- **不做开放式 agent。** 调查阶段只有 2–3 个有界工具，强制引用，输出是给人看的备忘而不是自动动作。
- **不一开始就通吃所有表单类型。** 先做 10-K 的风险因素章节，做透。

## 6. 路线图

| 阶段 | 内容 | 验收 |
|---|---|---|
| **1. 最小链路** | 1 家公司、2 期 10-K、只比风险因素，命令行打印变化列表 | 能在终端看到真实的跨期变化 |
| **2. 持仓覆盖** | 扩到 5 个 ticker，加排序与展示 | 能演示"4000 段 → 6 处真变化" |
| **3. 同行验证** | 加 agent 调查步骤：同行是否也改了 | 能区分行业性与公司特有信号 |
| **4. 演示打磨** | 输出格式、成本计数器、预热 | 30 秒内讲完 |

**贯穿始终的一件事**：手标 50 处变化，测量 Jev 在这个任务上的一致性。**这个数字比 demo 本身更能说明问题** —— 见 [ARCHITECTURE.md](ARCHITECTURE.md) 的风险一节。

## 7. 名字

**tell**，三个不相干的含义都指向同一件事：

- **扑克的 tell** —— 无意识露出的破绽。你看不到对手的牌，你看得到他改了行为。
- **tell apart** —— 分辨、看出差别。"这个产品做的事就是 tell 两个版本的差别。"
- **考古学的 tell** —— 层积土丘，一层压一层，靠层间差异读历史。

词源上，古英语 *tellan* 意为**计数** —— bank **teller**（柜员）本义是"数钱的人"。讲述和核账，本来是同一个动作。

> 仓库名 `tellagent`；命令行入口计划用 `tell`。
