# tellagent

> **市场最值得注意的，往往不是某个指标变了，而是多个指标开始互相矛盾。**

tellagent 是一个面向 **BTC 与 ETH** 的持续市场研究系统。它不断观察现货、衍生品和链上状态，利用 Jev 快速、低成本地判断每一帧市场状态；只有判断发生显著变化或证据互相冲突时，才唤醒昂贵的调查模型。

它不预测下一根 K 线，也不直接给出买卖建议。它回答三个更可靠的问题：

1. 现在发生了什么异常？
2. 哪些证据支持或反对当前市场叙事？
3. 系统过去在类似情况下判断得怎么样？

---

## 1. 问题

加密市场不缺数据。价格、成交量、资金费率、持仓量、期权、清算和链上活动已经散落在大量终端和仪表盘里。

真正困难的是：

- 指标太多，用户仍然要自己拼出结论。
- 单个指标经常误导，例如资金费率高不等于马上下跌。
- 大部分提醒只在指标越过静态阈值时触发，不能连续理解市场状态。
- AI 行情摘要容易只挑支持某个故事的数据，忽略反向证据。
- 回测经常使用后来修订的数据，产生无法察觉的未来信息泄漏。
- 产品会展示成功案例，却很少持续公布历史判断是否有效。

tellagent 不做另一个图表平台。它持续观察的是**市场状态和证据之间的冲突**。

典型事件包括：

- 价格上涨，但现货成交没有确认，持仓量和资金费率却快速扩张。
- 价格下跌，但持仓量下降得更快，卖压与去杠杆正在分离。
- ETH/BTC 走弱，但 Ethereum 链上使用与质押状态同时改善。
- 不同交易所的资金费率、基差或成交方向出现显著分歧。
- 期权隐含波动率先升高，现货实现波动率仍然平静。

## 2. 产品定位

**BTC/ETH 市场矛盾检测器。**

目标用户是主动研究 BTC 和 ETH、但不希望每天手工检查几十张图表的交易者与研究者。

默认运行节奏：

- 每 5 分钟采集并计算一帧市场状态。
- 每一帧都经过 Jev 的低成本结构化判断。
- 状态概率发生跃迁、持续越线或证据冲突时创建事件。
- 只有重要事件才调用昂贵模型生成研究摘要。
- 每日生成一次市场状态回顾。
- 每条事件在 6 小时、24 小时和 7 天后自动复盘。

第一版不是高频交易系统，也不执行交易。

## 3. 核心创新

### 3.1 廉价的眼睛，昂贵的手

Jev 的价值不是偶尔给一个事件打分，而是便宜到可以持续观察。

```text
代码        每 5 分钟计算可靠的市场特征
Jev         每一帧判断状态、矛盾和研究价值
事件引擎    观察判断概率如何变化，而不只看单次答案
调查模型    只有事件越线时才生成带证据的研究摘要
```

系统因此能记录市场从 `calm → developing → stressed → resolving` 的变化，而不是只在极端阈值被击穿后才报警。

### 3.2 矛盾，而不是更多指标

系统把指标组织成证据角色：

```text
价格行为     发生了什么
现货成交     是否有真实买卖确认
衍生品杠杆   是否由杠杆推动
期权市场     市场是否提前定价波动
链上状态     网络使用或资金移动是否确认
跨资产关系   BTC 与 ETH 是否同步
```

单项异常只是一条证据。多个角色共同形成异常或互相冲突时，系统才产生 `MarketEvent`。

### 3.3 强制展示正反证据

每一条判断都必须包含：

- 支持证据
- 反向证据
- 缺失证据
- 数据质量问题
- 可以推翻当前判断的条件

没有足够证据时，系统输出“不确定”，而不是补写一个听起来合理的原因。

### 3.4 Point-in-Time 证据

每条状态与事件冻结当时实际可见的数据、特征、问题集、模型版本和判断结果。之后数据即使被供应商修订，历史也不会被悄悄改写。

### 3.5 系统给自己打分

每条事件在未来固定时间自动复盘：

- 异常是否持续？
- 波动是否扩大？
- 杠杆是否解除？
- 反向证据是否成为主导？
- 当时的研究优先级是否合理？

用户看到的不只是当前提醒，还能看到该类提醒的历史表现。

## 4. 工作方式

```text
perceive   Coinbase · Deribit · Bitcoin · Ethereum
    ↓
compute    对齐时间 · 质量检查 · 特征 · 历史百分位 · 变化点
    ↓
observe    Jev 持续判断每帧状态，形成 JudgmentStream
    ↓
detect     概率跃迁 · 持续越线 · 跨市场矛盾 → MarketEvent
    ↓
explain    有界 investigator 生成带证据的可证伪摘要
    ↓
review     6h / 24h / 7d 后自动评价事件结果
```

确定性计算全部由代码完成。Jev 不计算收益率、百分位或相关性，只判断已经结构化的市场状态。

## 6. 与现有产品的区别

Glassnode、CryptoQuant、CoinGlass 和 Nansen 已经很好地解决了数据、图表、地址标签和阈值提醒问题。tellagent 不与它们比指标数量。

| 已有产品擅长 | tellagent 聚焦 |
|---|---|
| 展示大量指标 | 只报告跨来源异常和矛盾 |
| 单指标阈值提醒 | 持续的概率状态与状态跃迁 |
| 用户自己解释图表 | 自动组织支持与反向证据 |
| 当前市场解读 | 保存当时证据并持续复盘 |
| 单一风险分数 | 展示不确定性和失效条件 |

差异化不是“用了 agent”，而是**廉价连续判断 + 可检查证据 + 自动结果复盘**。

---

## 7. 它不做什么

- **不自动交易。** 输出是研究事件，不是订单。
- **不承诺预测收益。** 首先验证能否可靠识别风险状态。
- **不覆盖所有币种。** 只做 BTC 和 ETH，先做深度而不是广度。
- **不从价格走势编造新闻原因。** 没有可靠证据就不做因果归因。
- **不把模型置信度当成正确率。** 所有阈值都必须基于历史样本校准。
- **不隐藏失败。** 误报、失效和数据缺口都进入事件历史。

## 8. 最小版本

### 阶段 0：数据与回放

- Coinbase BTC-USD、ETH-USD 现货数据
- Deribit BTC、ETH 永续数据
- 本地不可变观测存储
- 历史回放与数据质量报告

验收：任意历史时点都能重建当时可见的原始状态。

### 阶段 1：持续判断

- 收益率、成交量、波动率、持仓量、资金费率和 ETH/BTC 特征
- 每 5 分钟生成 `MarketStateFrame`
- Jev 对每帧并行回答状态问题，形成 `JudgmentStream`
- 记录概率跃迁、持续性和判断稳定度

验收：连续运行成本可测，判断流可回放，普通时期保持稳定。

### 阶段 2：事件与证据

- 杠杆拥挤、去杠杆、现货背离、波动率扩张、跨资产分化
- 支持、反向、缺失证据
- CLI 事件收件箱和每日摘要

验收：排名优于简单阈值基线，所有结论可追溯。

### 阶段 3：链上与复盘

- Bitcoin Core 与 Ethereum 节点指标
- 6h / 24h / 7d Outcome Review
- 按事件类型展示历史有效率

验收：系统能够诚实展示自己在哪些市场状态下有效或失效。

## 9. 成功标准

第一阶段不以交易收益率作为唯一指标。依次验证：

1. 数据完整率和时点可重放性。
2. Jev 每日持续观察的实际成本和延迟。
3. 状态概率在普通市场中的稳定性。
4. 历史重大事件的召回率与提前量。
5. 普通市场中的每周误报数量。
6. 用户认为“值得进一步研究”的事件比例。
7. 各事件类型在 6h / 24h / 7d 的结果分布。
8. 在严格样本外测试中，风险策略是否改善最大回撤或风险调整后收益。

只有前七项稳定后，才讨论投资收益。
