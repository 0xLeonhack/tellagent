# 准确性与真实性验证

> 复核时间：2026-10-17。数据来源：Coinbase Exchange 公共 K 线、Deribit 公共 ticker 与
> funding history。本文所有数字都可以用文中命令重新生成。

这份文档回答两个问题：

1. 系统记录和判断的数据是真的吗，判断能被独立复现吗？
2. Observer 打分和 Gate 比之前准确在哪里，依据是什么？

## 一、数据不是编造的：四条独立证据

审计命令：

```bash
uv run python -m tellagent audit --limit 200
uv run python -m tellagent audit --limit 200 --live
```

| 检查 | 证明什么 | 实现 |
| --- | --- | --- |
| `source_integrity` | 生产代码不导入 `random` / `faker` / `mock`，运行路径没有随机数或假数据入口 | 对 `tellagent/*.py` 做 AST 扫描 |
| `frame_ids` | 每帧的 `frame_id` 能由该帧自己的字段重新算出，响应哈希是真实 SHA-256 | 用当前或旧版指纹算法重算并比对 |
| `frame_timestamps` | 采集时间不在未来，来源时间不晚于采集时间，帧按时间单调、ID 唯一 | 独立解析 ISO 时间并检查时钟偏差（≤5 秒） |
| `judgment_reproduction` | 当前模型版本（v4）的每条规则判断都能从冻结帧精确重算；旧版本判断与帧内冻结的确定性评估一致 | 另一条代码路径调用 `RuleBasedObserver.judge(frame)`；旧版本因打分代码已改变，只做一致性核对并在结果中单列 |

`--live` 还会重新请求 Coinbase 和 Deribit：

- 用**独立实现**的公式重算价格、1h/6h 涨跌、6h 已实现波动、成交量变化和 6h 量比，容差 `1e-9`；
- Funding 是每秒变化的实时预测，允许绝对差 `5e-5` 或相对差 25%；
- Open Interest 随秒级成交变动，允许相对差 2%；
- Coinbase 收盘价与 Deribit 指数价交叉核对，价差超过 3% 判为异常；
- **回查历史帧**：拿每一帧记录时的 `received_time`，用交易所当前仍保留的
  小时 K 线重新计算当时的现货指标，再与该帧记录值逐项比较。伪造的帧无法通过
  这一关，因为它不可能预先匹配它没有见过的公开 K 线。
- **K 线结算期**：实测 Coinbase 会在整点后继续修订刚结束小时 K 线的收盘价和
  成交量（2026-10-17 04:00 的 BTC 收盘价和成交量在几分钟内变化过）。因此采集器
  现在等 `CANDLE_SETTLEMENT_SECONDS = 300` 秒才把该小时当作历史；审计也不会对
  “记录时间距该 K 线收盘不足 5 分钟”的帧做精确回查，而是明确标记为跳过。
  这不是放宽标准：更早的帧仍然逐项精确比较，跳过数量会写进审计详情。

审计时（采集器已停止），默认账本（16 帧）和评估账本（80 帧）上的上述检查全部通过。
当前打分版本是 v4；评估账本中的 64 条 v4 判断已精确复现，16 条旧版本判断无法用
已经改变的打分代码精确重算，但都与各自帧内冻结的评估逐条一致。两个资产各有
35 帧落在交易所保留的 K 线窗口内并与公开历史逐项一致；各有 5 帧因为采集时
K 线仍在 5 分钟结算期内而被明确跳过。Coinbase 与 Deribit 的交叉价差在 ±0.4%
以内，属于正常基差。

**诚实边界**：审计能证明“记录与公开数据一致、判断由记录决定论地产生”，
不能证明一个恶意程序同时伪造数据和判断且始终自洽。因此系统同时保留
原始响应哈希、来源时间、独立重算和公开可复查的交易所接口，让这种伪造在外部也可发现。

## 二、Observer 打分：从“假概率”到证据加权分布

### 旧问题

旧实现先给每个状态一个规则分，再做 `normalized score / max` 一类归一化，结果常见的
是 `spot_confirmed_down 100% · quiet 0% · spot_confirmed_up 0%`。这不是概率，
而是一张“赢家通吃”的标签；`quiet` 和竞争假设被压成 0，置信度也接近固定值。

### 新实现（`tellagent/scoring.py`，`model_version = market-state-v4`）

1. 把每个因子变成有方向的标准化强度（z 分数，裁剪到合理范围）：
   `price_z`、`volume_z`、`oi_z`、`funding_z`，加上量比和活动度。
2. 证据强度先经过**方向门控**：没有真实价格位移时，方向类状态不能仅凭成交量或 OI 获胜。
3. 13 个状态各有一个 logit。方向类共享“证据基座”，再按现货确认、杠杆扩张、
   持仓收缩、广泛参与区分；`quiet`、`conflicting`、`insufficient_data` 有独立项。
4. 对 logits 做 softmax，得到严格为正、总和为 1 的完整分布。
5. 给规则标签一个固定 `LABEL_BONUS`，保证 `selected_value == argmax`，同时保留
   其他假设的概率质量。
6. 置信度不是最大概率本身，而是：
   `(0.35 + 0.50 × 相对领先幅度) × 数据质量因子 × 冲突折扣`，上限 0.85。

这样做的好处是可检验的：

- 测试覆盖 11 类规则场景，断言标签始终等于 argmax；
- 上涨与下跌证据镜像对称（同强度互换，概率严格相等）；
- OI 越强，杠杆假设概率越高、未确认走势概率越低；
- 缺失 OI 时 `insufficient_data` 必须成为最大项；
- 数据陈旧会提高 `insufficient_data` 概率并降低置信度。

### OI 的口径修正

不同采集间隔的 OI 原始变化不可直接比较：60 秒涨 0.1% 与 5 分钟涨 0.1% 不是同一个信号。
现在先归一化为**每小时变化率**再与阈值比较；没有历史 OI 时保持缺失，绝不用短周期值冒充 1h 值。

## 三、Gate：新信号优先，稳定重复才静默

Gate 的目标不是单纯减少调用，而是在不漏掉材料性市场信号的前提下减少重复调用。
Observer 发现新的可行动状态后立即交给 Agent；Agent 仍可选择 `monitor`，只有它决定继续研究时
才调用强 Analyst。相同状态和证据关系没有材料变化时，后续帧保持静默。

| 规则 | 目的 |
| --- | --- |
| 数据不足时不放行，除非恢复 | 避免拿缺失 OI 的方向标签做研究 |
| 首次出现的可行动状态立即放行 | 不因等待确认错过短时市场信号 |
| 启发式权重低于 `0.40` 不放行 | 排除证据过弱的标签变化 |
| 降级到低优先级时静默 | 不把“变得不重要”当成新事件 |
| 从 `insufficient_data` 恢复到材料性 `watch` 状态也放行 | 数据恢复后的第一条真实信号不会被吞掉 |
| 概率升降、优先级和冲突关系发生材料变化时更新事件 | 捕捉信号增强和弱化 |
| `event_open` 来自账本最后一条决策 | 避免把“有历史”误当成“事件仍开着” |

`evaluate` 命令会在同一批实盘判断上对照旧/新 Gate。Gate 策略改变后不保留旧统计数字，
避免用历史样本结果描述当前逻辑；应在当前账本上重新运行命令获取结果。

## 四、阈值来自真实分布，不是拍脑袋

30 天、719 个小时的实测分布（`uv run python -m tellagent evaluate --days 30`）：

| 特征 | BTC p50 / p90 | ETH p50 / p90 | 当前默认阈值 |
| --- | --- | --- | --- |
| \|1h 涨跌\| | 0.15% / 0.54% | 0.19% / 0.70% | 0.60% |
| \|1h 成交量变化\| | 31.0% / 92.1% | 34.4% / 103.1% | 80% |
| 6h 量比 | 0.94x / 2.53x | 0.96x / 2.49x | 确认线 1.5x |
| \|Funding (8h)\| | 0.00355% / 0.0106% | 0.00267% / 0.0083% | 0.012% |

关键发现：**小时成交量的自然波动中位数就有 31%**。旧测试里把 8%–10% 的成交量变化
当作“强现货确认”，实际上只相当于 p10–p20，几乎不提供信息。现在：
- 默认阈值取两个资产 p90 附近的保守值；
- “现货确认”优先看 6h 量比 ≥1.5x，而不是单小时量变；
- Funding 极端阈值接近 p90，只在约 7%–10% 的小时里触发。

默认值刻意取整、跨资产共用，不逐资产拟合最近 30 天，避免过拟合；需要时可通过
`strategy_thresholds` 按资产覆盖。

### 前向信息检验

阈值只有“之后确实更容易出现大波动”才有意义。以阈值 0.6% 划分大涨跌：

| 资产 | 大涨跌后 1h 波动 | 平静后 1h 波动 | 大涨跌后 3h 波动 | 平静后 3h 波动 | 3h 同向延续率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| BTC | 0.40% | 0.23% | 0.56% | 0.41% | 48.3% |
| ETH | 0.46% | 0.28% | 0.71% | 0.52% | 48.3% |

结论：
- 大涨跌之后波动显著更高，说明阈值捕捉到了“活动状态”；
- 同向延续率约 48%，**没有方向性优势**。因此系统只把状态当作研究线索，
  不据此预测涨跌或交易，这和产品定位一致；
- 成交量确认后 3h 波动：BTC 0.58% vs 0.52%，ETH 0.77% vs 0.59%；
  BTC 的成交量确认对方向延续更有区分度（56.4% vs 31.6%），ETH 几乎没有（49.2% vs 46.4%）；
- Funding 极端后的 8h 收益在样本内方向不一致（BTC −0.07%，ETH +0.61%），
  因此只作为“拥挤/情绪”证据，不作为方向信号。

### 为什么没有“全状态历史回测”

公开接口不提供历史 Open Interest，Deribit `get_funding_rate_history` 只提供 funding。
没有历史 OI 就无法重建 `leverage_expansion`、`position_unwind` 等状态。
系统不发明这段数据，所以只用价格、成交量、量比和 funding 做可验证的历史检验；
完整状态回测需要自建 OI 采集历史，这是明确的后续工作。

## 五、复现方法

```bash
# 1. 全量测试（含打分矩阵、Gate 生命周期、审计、评估）
uv run pytest

# 2. 离线审计：帧 ID、哈希、时间、概率、判断复现
uv run python -m tellagent audit --limit 200

# 3. 联网审计：独立重算 Coinbase/Deribit 指标
uv run python -m tellagent audit --limit 200 --live

# 4. 30 天经验分布、前向检验、旧/新 Gate 对照
uv run python -m tellagent evaluate --days 30 --json .tellagent/eval/accuracy.json
```

## 六、剩余限制

- 实盘 Gate 对照样本仍小，结论是机制性的，不是统计显著的；
- 历史 OI 不可得，无法做全状态样本外回测；
- 概率是规则证据的 softmax 分布，不是校准过的真实概率；置信度是启发式强度，
  文档和 UI 中明确标注为“启发式分数”；
- 1 小时 OI 变化依赖进程内相邻采样；间隔过大时保持缺失；
- 最新小时 K 线要等 5 分钟结算后才进入计算，因此现货价格最多有约 5 分钟的
  小时级延迟；这是为了避免使用交易所仍在修订的收盘价和成交量；
- Funding 与 OI 是实时值，两次请求之间会自然漂移，审计使用相应的实时容差。
